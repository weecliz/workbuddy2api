# 数据库支持（MySQL / DB2 / SQLite）

本项目通过 **一个配置点** 切换数据库：`ADMIN_DB_TYPE` + 分项连接参数（写在 `.env` 里），
也可以在 **启动命令上直接指定**（见下面「0. 启动命令指定数据库」）。
业务代码全部走 ORM，只有少量原生 SQL（查「列是否存在」、补列、建库 / 建 schema / 建数据文件目录）由方言层适配。

| 类型 | 适用场景 | 驱动 |
| --- | --- | --- |
| `sqlite` | **默认**：单机 / 试跑 / 小规模部署，零额外安装 | 无（标准库 `sqlite3`） |
| `mysql` | 生产（高并发） | `pymysql` |
| `db2` | 生产（IBM 环境） | `ibm_db_sa` |

> **默认已是 SQLite**：什么都没配时（`.env` 里没有数据库配置、命令行也没给 `--db-type`）
> 走 `DEFAULT_DB_TYPE = "sqlite"`，即 `./data/workbuddy_admin.db`，克隆下来直接就能跑。
> **生产环境请在 `.env` 里显式写 `ADMIN_DB_TYPE`**，不要依赖这个兜底值。

| 层级 | 文件 | 职责 |
| --- | --- | --- |
| 配置中心 | `admin/db_config.py` | 读 env / `.env`，生成 SQLAlchemy URL、连接池参数 |
| 方言适配 | `admin/db_dialect.py` | 引用符、类型映射、系统表查询、能否建库 / 建 schema |
| 引擎与迁移 | `admin/db.py` | 建引擎、事件（DB2 设 current schema）、建表、增量补列 |
| ORM 模型 | `admin/models.py` | 表结构；长文本列在 DB2 上编译成 CLOB |

自检当前生效配置（密码打码）：

```bash
python -m admin.db_config
```

## 0. 启动命令指定数据库

启动时可以不改 `.env`，直接用命令行参数临时切换（**优先级高于 `.env`，只影响本次进程，不回写配置文件**）：

```bash
# MySQL（用 .env 或这里的参数）
python main.py

# SQLite：单文件库，零依赖
python main.py --db-type sqlite --db-name ./data/workbuddy_admin.db

# DB2
python main.py --db-type db2 --db-name WBADMIN --db-schema WBADMIN

# 列出所有支持的类型后退出
python main.py --list-db-types
```

| 参数 | 对应的环境变量 | 说明 |
| --- | --- | --- |
| `--db-type` | `ADMIN_DB_TYPE` | `sqlite` \| `mysql` \| `db2` |
| `--db-host` | `ADMIN_DB_HOST` | 主机（SQLite 忽略） |
| `--db-port` | `ADMIN_DB_PORT` | 端口（留空用该类型默认值） |
| `--db-user` | `ADMIN_DB_USER` | 账号（SQLite 忽略） |
| `--db-password` | `ADMIN_DB_PASSWORD` | 密码（SQLite 忽略） |
| `--db-name` | `ADMIN_DB_NAME` | 库名；**SQLite 时是数据文件路径** |
| `--db-schema` | `ADMIN_DB_SCHEMA` | DB2 目标 schema |
| `--db-options` | `ADMIN_DB_OPTIONS` | 方言原生参数串，如 `charset=utf8mb4` |

几点行为说明：

- 什么都不给时按 `DEFAULT_DB_TYPE`（当前 `sqlite`）走，即 `./data/workbuddy_admin.db`。
- 只要显式给了 `--db-type`，就会忽略 `.env` 里的 `ADMIN_DATABASE_URL`（避免整串 URL 把分项参数顶掉）。
- 依赖自检会跟着变：选 `sqlite` 就不要求装 `pymysql`，选 `db2` 才要求 `ibm_db_sa`。
- 启动日志和 `start_admin.bat` 的横幅都会回显本次生效的数据库，选错了一眼能看出来。
- 参数会在自动切换到虚拟环境时一并透传，不影响解释器自愈逻辑。

常用切库方式：

```bash
python main.py                                   # 默认 SQLite，零依赖直接跑
python main.py --db-type mysql --db-password x   # 临时改用 MySQL（其余取 .env 或默认值）
```

批处理同样支持（参数原样转发给 `main.py`）：

```bat
scripts\start_admin.bat --db-type sqlite --db-name ./data/wb.db
scripts\start_admin.bat --list-db-types
```

## 1. MySQL（生产推荐）

```ini
ADMIN_DB_TYPE=mysql
ADMIN_DB_HOST=127.0.0.1
ADMIN_DB_PORT=3306
ADMIN_DB_USER=root
ADMIN_DB_PASSWORD=你的密码
ADMIN_DB_NAME=workbuddy_admin
ADMIN_DB_OPTIONS=charset=utf8mb4
```

- 驱动：`pip install pymysql`
- 启动时若库不存在会自动 `CREATE DATABASE ... CHARACTER SET utf8mb4`；
  不想让它建库设 `ADMIN_DB_AUTO_CREATE=0`（此时库必须已存在）。

旧写法仍然支持，且优先级更高：

```ini
ADMIN_DATABASE_URL=mysql+pymysql://root:pwd@127.0.0.1:3306/workbuddy_admin?charset=utf8mb4
```

## 2. IBM Db2（LUW）

### 2.1 安装驱动

```bash
pip install ibm_db_sa          # SQLAlchemy 的 DB2 方言，会带上原生驱动 ibm_db
```

Windows 需要 Python 与 DB2 实例位数一致（64 位 Python 对 64 位实例）。

### 2.2 数据库准备（应用不负责建库）

DB2 的「建库」是实例级操作，本应用不会去做，请先在服务器上准备好数据库：

```sql
-- 建议用较大的页大小，避免行长超限（SQLSTATE 54010）
CREATE DATABASE WBADMIN AUTOMATIC STORAGE YES
  USING CODESET UTF-8 TERRITORY CN PAGESIZE 16 K;

CONNECT TO WBADMIN;
-- schema 可以由应用自动创建（ADMIN_DB_AUTO_CREATE=1），也可以手工建：
CREATE SCHEMA WBADMIN AUTHORIZATION DB2INST1;
```

> 若 `PAGESIZE 16 K` 报缓冲池相关错误，先建对应缓冲池：
> `CREATE BUFFERPOOL BP16K IMMEDIATE SIZE 1000 PAGESIZE 16 K;`

### 2.3 配置

```ini
ADMIN_DB_TYPE=db2
ADMIN_DB_HOST=127.0.0.1
ADMIN_DB_PORT=50000
ADMIN_DB_USER=db2inst1
ADMIN_DB_PASSWORD=你的密码
ADMIN_DB_NAME=WBADMIN        # 必须已存在的数据库
ADMIN_DB_SCHEMA=WBADMIN      # 目标 schema；留空则用 DB2 默认 schema（= 用户名大写）
```

等价的显式连接串写法：

```ini
ADMIN_DATABASE_URL=db2+ibm_db://db2inst1:pwd@127.0.0.1:50000/WBADMIN?currentSchema=WBADMIN
```

### 2.4 类型映射（自动生效）

| 语义 | MySQL | DB2 |
| --- | --- | --- |
| 自增主键 | `INT AUTO_INCREMENT` | `INT GENERATED BY DEFAULT AS IDENTITY` |
| 时间 | `DATETIME` | `TIMESTAMP` |
| 浮点 | `FLOAT` | `DOUBLE` |
| 布尔 | `TINYINT(1)` | `SMALLINT` |
| 长文本（`Text`） | `TEXT` | `CLOB` |
| `key_full` | `VARCHAR(2048)` | `CLOB`（只用于后台展示，不参与查询条件） |

另外：

- 每条连接都会执行 `SET CURRENT SCHEMA ...`，连接池复用也不会串到别人的 schema；
- 「列是否存在」查 `SYSCAT.COLUMNS`（MySQL 查 `INFORMATION_SCHEMA.COLUMNS`）；
- 增量补列时 DB2 的 LOB 类型不允许 `DEFAULT`，方言层会自动省略；
- 标识符按 DB2 习惯用双引号（MySQL 用反引号），`key` / `value` 这类保留字已正确处理。

### 2.5 常见报错

| 现象 | 处理 |
| --- | --- |
| `NoSuchModuleError: ... sqlalchemy.dialects:db2.ibm_db` | 没装方言包：`pip install ibm_db_sa` |
| `SQLSTATE 54010`（行太长） | 用更大的页重建数据库：`PAGESIZE 16 K` / `32 K` |
| `SQLSTATE 42710`（对象已存在） | 无害，忽略；或设 `ADMIN_DB_AUTO_CREATE=0` |
| 连不上（`SQL30081N`） | 确认 50000 端口与实例监听配置；`db2 get dbm cfg | findstr SVCENAME` |

## 3. SQLite（单文件）

### 3.1 安装

无需安装任何东西——驱动 `sqlite3` 是 Python 标准库。**也不用改 `requirements.txt`。**

### 3.2 配置

```ini
ADMIN_DB_TYPE=sqlite
ADMIN_DB_NAME=./data/workbuddy_admin.db
```

- **只认 `ADMIN_DB_NAME`**，把它当数据文件路径；`ADMIN_DB_HOST` / `PORT` / `USER` / `PASSWORD` 全部忽略。
- 相对路径以 **项目根目录** 为基准（不受运行时 CWD 影响）；目录与文件都会自动创建。
- 也支持绝对路径 `D:/data/workbuddy_admin.db`、`/var/lib/wb/a.db`，
  以及内存库 `:memory:`（进程退出即丢，仅测试用）。
- 等价连接串写法：`ADMIN_DATABASE_URL=sqlite:///./data/workbuddy_admin.db`

### 3.3 与 MySQL / DB2 的差异

| 项目 | 行为 |
| --- | --- |
| 建库 | 不需要；SQLAlchemy 首次连接时自动创建数据文件 |
| 启动准备 | 只负责创建数据文件所在目录 |
| 连接池 | `NullPool`（每会话一条连接）；`POOL_SIZE` 等参数自动忽略 |
| 写锁 | 默认等锁 30 秒（可用 `ADMIN_DB_CONNECT_TIMEOUT` 调整），避免并发写直接报 `database is locked` |
| 跨线程 | 已开启 `check_same_thread=False`（调度线程与请求线程共用引擎） |
| 类型 | 自增主键 `INTEGER`、时间 `DATETIME`、长文本 `TEXT` |
| Windows 服务依赖 | 无（`service_admin.py` 不声明依赖） |

### 3.4 注意事项

> **SQLite 是单写者模型**：同一时刻只允许一个写事务，高并发写入（多账号轮询 + 用量落库 + 定时任务）
> 会显著变慢甚至超时。仅建议用于单机、试跑或低并发场景；生产高并发请用 MySQL / DB2。

- 备份就是复制那个 `.db` 文件（建议先停服务，或 `VACUUM INTO 'backup.db'`）。
- 数据文件已在 `.gitignore` 中忽略，勿提交进仓库。

## 4. 新增一种数据库

1. 在 `admin/db_dialect.py` 里加一条 `DbDialect`（scheme、默认端口、引用符、类型映射、系统表 SQL、
   标识符大小写 `name_case`、是否文件库 `file_based`），注册进 `_DIALECTS` 与 `_ALIASES`；
2. 文件库（如 SQLite）在 `admin/db_config.py` 的 `_normalize_sqlite_target` 旁边补一个 URL 规整函数，
   并在 `DbConfig.engine_kwargs()` 里给出合适的连接池；
3. 在 `requirements.txt` 里注明对应驱动包；
4. 需要的话在 `admin/models.py` 里给特殊类型加 `.with_variant()`；
5. `.env` 里写 `ADMIN_DB_TYPE=<新类型>` 即可，`admin/db.py` 及以上业务代码无需改动。
